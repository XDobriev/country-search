# Архитектурная документация (DESIGN.md)

Документ описывает технические решения, алгоритмическую сложность и принципы проектирования приложения **Country Search**.

---

## 1. Механизм отмены устаревших запросов и гонки ответов

### Проблема «гонки ответов» (Race Condition)

При живом поиске пользователь непрерывно вводит символы (например, сначала `sp`, затем `spain`). Запросы отправляются асинхронно. Если сервер или сетевой маршрут обрабатывает запрос `sp` дольше, чем `spain`, то ответ на `sp` может прийти позже ответа на `spain`. Без должного контроля более старый ответ перезапишет на экране актуальный результат поиска.

### Почему именно `AbortController`, а не флаги («последний запрос» / timestamp)

Существует соблазн решить проблему на клиенте наивным способом — сохранять ID или timestamp последнего ввода и игнорировать ответ, если его ID устарел (`if (requestId !== currentRequestId) return`). Такое решение является антипаттерном в продакшене по следующим причинам:

1. **Расход сетевых ресурсов и батареи**: Запрос физически продолжает лететь по сети, сервер тратит ресурсы на его обработку, а клиент скачивает и парсит ненужный объем данных (JSON со списком десятков стран). На мобильных устройствах это приводит к лишнему расходу трафика и разряду аккумулятора.
2. **Лимит одновременных HTTP-соединений**: Браузеры имеют жесткое ограничение на количество одновременных TCP-соединений к одному домену (обычно до 6 соединений в HTTP/1.1). Пачка «висящих» устаревших запросов блокирует отправку действительно важного актуального запроса (head-of-line blocking).
3. **Реальная отмена на сетевом уровне**: `AbortController` связывается с браузерным Fetch API через `AbortSignal`. При вызове `abort()` браузер немедленно обрывает сетевой стрим (отправляя TCP RST или HTTP/2 frame `RST_STREAM`) и освобождает системный сокет.

### Момент отмены: немедленно при каждом изменении ввода

В `SearchCoordinator.onInput` предыдущий активный сетевой запрос отменяется **мгновенно** в момент нажатия пользователем любой клавиши, не дожидаясь срабатывания таймера debounce. Если бы отмена происходила только по истечении интервала debounce, то в течение этих 350 миллисекунд старый сетевой ответ успел бы завершиться и перерисовать интерфейс под уже неактуальный текст.

### Различение ошибок отмены и сбоев сети

В блоке `catch` критично отделять три разных сценария:

- **`AbortError` (отмена пользователем / смена ввода)**: это штатное поведение, а не ошибка. Данное исключение категоризируется с флагом `shouldDisplayToUser: false`, результат подавляется, экран не показывает ошибку и не дергается.
- **`TimeoutError` (таймаут сервера)**: формируется через `AbortSignal.timeout` / встроенный таймер отсечки. Категоризируется как `TIMEOUT` (`shouldDisplayToUser: true`, `canRetry: true`).
- **Сетевой сбой или HTTP 5xx**: категоризируется как ошибка с отображением понятного текста на русском языке и возможностью повторить запрос.
- **HTTP 404**: по спецификации `countries.dev`, статус 404 означает отсутствие совпадений. Функция `searchCountries` возвращает пустой массив `[]`, а интерфейс переходит в дружелюбное состояние `EMPTY` без признаков ошибки.

## 2. Обоснование выбора задержки debounce

В приложении установлена задержка debounce в **350 мс** (`DEFAULT_DEBOUNCE_DELAY = 350`).

### Анализ физиологии ввода и сетевого оверхеда:

- Средняя скорость печати человека на клавиатуре составляет 180–300 знаков в минуту, что соответствует интервалу между нажатиями клавиш в диапазоне **200–350 мс**.
- **Что произойдет при отсутствии debounce (0 мс)**:
  При вводе слова «Germany» (7 символов) приложение отправило бы 7 сетевых запросов. Даже при условии мгновенной отмены предыдущих это создает паразитный всплеск сетевых пакетов, лишнюю нагрузку на сетевой стек браузера, триггерит CORS preflight-запросы и может привести к бану по IP или ответу `429 Too Many Requests` от публичного API `countries.dev`.
- **Что произойдет при чрезмерно большой задержке (> 700–1000 мс)**:
  Интерфейс теряет ощущение «живого» поиска. Пользователь напечатал запрос, закончил ввод и вынужден ждать целую секунду только для того, чтобы запрос хотя бы начал отправляться. Это воспринимается как зависание интерфейса.
- **Вывод**:
  Значение **350 мс** является выверенным оптимумом. Пока пользователь печатает слово, таймер постоянно перезапускается, не нагружая сеть промежуточными буквами (`g`, `ge`, `ger`). Как только в наборе возникает естественная пауза в 350 мс, запрос отправляется в сеть. При этом клик по подсказке или выбор из истории выполняет поиск **мгновенно** без задержки.

## 3. Анализ алгоритмической сложности (Big O)

### 3.1. Функция преобразования `mapCountryResponse(raw)`

```typescript
export function mapCountryResponse(raw: RawCountry): CountryCard;
```

- **Временная сложность**:
  - Чтение и валидация базовых полей (строки, числа): $O(1)$.
  - Форматирование населения и площади через `Intl.NumberFormat`: $O(1)$.
  - Обработка языков (`raw.languages`): обход массива длины $L$ с дедупликацией через `Set` — $O(L)$.
  - Обработка валют (`raw.currencies`): обход массива длины $C$ — $O(C)$.
  - Обработка границ (`raw.borders`): фильтрация строк длины $B$ — $O(B)$.
  - Обработка временных зон (`raw.timezones`): обход длины $T$ — $O(T)$.

  Поскольку для любого реально существующего государства $L \le 12$, $C \le 5$, $B \le 14$, $T \le 12$ являются малыми константами, ограниченными физическим миром, операция преобразования одной страны выполняется за строго константное время **$O(1)$**.

  Для массива результатов ответа из $N$ стран суммарная сложность преобразования составляет **$O(N)$**.

- **Пространственная сложность**:
  - Создание нового нормализованного объекта `CountryCard`: $O(1)$ дополнительной памяти на страну (или $O(N)$ для всего массива результатов).

---

### 3.2. Кэширование и дедупликация запросов (`SearchCache`)

- **Нормализация ключа**:
  Приведение к нижнему регистру и обрезка пробелов `query.trim().toLowerCase()` выполняется за **$O(K)$**, где $K$ — длина поисковой строки (обычно $K \le 50$).

- **Операции `get`, `has`, `set`**:
  Используется структура `Map<string, CacheEntry<T>>`.
  - Поиск в хэш-таблице: в среднем **$O(1)$**.
  - Обновление позиции LRU (вытеснение устаревших): удаление и повторная вставка ключа в конец итератора `Map` — **$O(1)$**.
  - Ограничение размера кэша `maxSize = 100`: если размер превышен, удаление самого старого элемента `map.keys().next().value` выполняется за **$O(1)$**.

- **Дедупликация одновременных запросов (In-Flight Promise Sharing)**:
  - Поиск уже летящего запроса по ключу: $O(1)$.
  - Добавление подписчика и создание независимой Promise-обертки: $O(1)$.
  - Отмена подписчика: уменьшение счетчика `subscriberCount` — $O(1)$. Отмена базового сетевого запроса происходит только тогда, когда отписались **все** параллельные слушатели.

- **Пространственная сложность**:
  - $O(M \cdot D)$, где $M$ — максимальное количество закэшированных запросов (`maxSize = 100`), $D$ — средний размер полезной нагрузки (массива стран). Память жестко ограничена сверху и защищена от утечек алгоритмом LRU.

---

### 3.3. История поисковых запросов (`SearchHistory`)

- Хранение в `localStorage` (ключ `country_search_history`, лимит `maxItems = 5`).
- Чтение и сериализация JSON массива из 5 строк: **$O(1)$** по времени и памяти.
- Проверка на дубликаты без учета регистра: **$O(H)$**, где $H \le 5$, то есть **$O(1)$**.

## 4. Принципы чистого кода (Clean Code)

| Принцип                                                            | Где и как применен в кодовой базе                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Single Responsibility Principle (SRP)**                          | Каждый модуль решает строго одну задачу: <br>• `src/api/searchCountries.ts` — только транспортный уровень и проверка HTTP-ответов.<br>• `src/utils/classifyError.ts` — чистая классификация ошибок и определение стратегии показа пользователю.<br>• `src/utils/debounce.ts` — изолированная утилита тайминга функций.<br>• `src/utils/mapCountryResponse.ts` — чистая функция трансформации DTO в модель карточки.<br>• `src/utils/searchCache.ts` — кэш и дедупликация in-flight промисов.<br>• `src/utils/searchHistory.ts` — персистентное хранилище недавних поисков.<br>• `src/services/SearchCoordinator.ts` — управление состоянием и оркестрация жизненного цикла запросов. |
| **Open/Closed Principle (OCP)**                                    | Класс `SearchCoordinator` открыт для расширения через опции конструктора (`SearchCoordinatorOptions`): можно передать кастомный кэш, историю или задержку debounce, не модифицируя внутреннюю логику класса.                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Liskov Substitution Principle (LSP)**                            | Класс `HttpError` расширяет стандартный JavaScript `Error`, полностью сохраняя контракт родителя (`name`, `message`, `stack`) и добавляя типизированное свойство `status`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Interface Segregation Principle (ISP)**                          | Клиентский код зависит от компактных и специфичных интерфейсов (`CountryCard`, `ClassifiedError`, `SearchState`, `SearchBarProps`), не требуя знания о внутреннем устройстве исходного сырого JSON API (`RawCountry`).                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Dependency Inversion Principle (DIP)**                           | `SearchHistory` зависит от абстракции стандартного интерфейса `Storage`, а не напрямую от глобального объекта `window.localStorage`. Это позволило в тестах передавать `MemoryStorage` и изолировать тесты от окружения браузера.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Don't Repeat Yourself (DRY)**                                    | Форматирование чисел и валют вынесено в утилиты, а генерация повторяющихся DOM-узлов инкапсулирована в типобезопасный микро-билдер `src/ui/dom.ts`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **Безопасность (No innerHTML / XSS Defense)**                      | По требованиям спецификации категорически запрещено использование `innerHTML` и `insertAdjacentHTML` для динамического контента. Вся верстка создается исключительно через безопасные API браузера (`document.createElement`, `document.createTextNode`, `textContent`), что полностью исключает возможность XSS-инъекций через данные API.                                                                                                                                                                                                                                                                                                                                          |
| **FIRST (Fast, Independent, Repeatable, Self-Validating, Timely)** | Тестовый набор из 50 модульных и интеграционных тестов выполняется за <1.5 секунды, не зависит от реальной сети (сеть полностью замокирована) и покрывает позитивные, граничные и аварийные сценарии.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
